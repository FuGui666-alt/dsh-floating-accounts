# 多站点、多账号升级规格

## 状态与授权边界
状态：已批准，进入实现。用户已要求升级“站点 → 账号 → 凭据”，并于2026-11-19通过范围确认选择“按此方案升级”；首版范围及旧数据迁移方式以本规格为准。

首版交付：源码升级、构建产物、离线升级包、回归证据与操作说明。**安装到现有DSH、真实账号数据迁移、用已保存凭据查询余额、自动导入供应商Key和重启，不在本轮源码实现授权中。** 这些动作各自保留明确确认入口，不能沿用之前已消耗的安装/GET授权。

目标版本：1.1.0。Windows当前运行环境已核实为win32、Node v24.19.0；现有插件1.0.2，ESM、DPAPI CurrentUser、宿主React ModuleLoader与Typert RPC保持，不安装额外依赖。

## 选择的方案
| 方案 | 收益 | 代价/反选原因 |
|---|---|---|
| 只在每条旧账号上加协议 | 改动少 | 同站配置重复；账号身份与多Key仍混在一起，不满足本次目标 |
| 站点配置＋独立账号＋账号内凭据（推荐） | 每站协议独立、同站多邮箱账号、多Key归属明确；保留现有加密owner | 需schema迁移及RPC/UI配对升级 |
| 一次接入所有网页登录/OAuth/云财务 | 覆盖更多授权类型 | 多平台接口未证实，须新增签名/令牌刷新/权限体系；本版不猜测实现 |

推荐第二种；不是重写成另一个服务，也不复制独立用量插件的自动轮询或宽松解析。

## 用户看见的结构
1. 面板按站点分组。站点设置：名称、模型Base URL、查询协议、额度单位/倍率或“未配置”。
2. 同一站点可添加多个账号：显示名、可选邮箱/身份备注。邮箱仅用于用户区分，不验证邮箱、不收集密码、不作为认证或自动合并依据。
3. 每个账号可保存多个模型API Key及原有分组密钥；凭据仅属于该账号，选择一把模型Key作为该账号的余额查询Key。显示“已保存”而不回显、复制、导出Key正文。
4. 每个账号一个“查询余额”按钮；没有可用协议或Key时显示具体原因，不显示0，不发网络请求。不提供批量查询按钮或后台轮询。
5. 余额区明确分开账户钱包和所选Key额度；DeepSeek显示分币种总可用/赠金/充值分项，未提供Key独立额度时写“接口未提供”，不是无限额度。
6. 不合计站点钱包、不合计跨币种、不根据相同网址或邮箱昵称合并账号。不同账号可保存相同Key，但不推断这是不同钱包。

## 数据与唯一owner
继续由现有AccountVault持有加密文件，schema2逻辑数据包含站点列表及账号列表；账号内包含凭据列表。不新建明文secret sidecar、独立余额数据库或第二个vault。

| 对象 | 字段与边界 |
|---|---|
| 站点 | UUID、name、baseURL、可空balanceQuery、updatedAt；协议/路径/单位只从此对象取得 |
| 账号 | 原UUID保留、siteId、name、可空identityLabel、credentials、可空balanceCredentialId、updatedAt |
| 凭据 | UUID、label、kind=`model-api-key`或`group-key`、secret、updatedAt；限定在所属账号内 |
| 总状态 | schema=2、revision、sites、accounts；全局修订号统一覆盖站点/账号/凭据变化 |

限制：最多100站点、100账号、每账号10凭据；名称1–80字符、身份备注最多120字符、secret不超过8192且禁止空白/控制字符；加密文件仍不超过4MiB。所有ID、外键、凭据选择、重复ID和类型均在读写两端校验。账号可以先无Key建档，但查询必须有明确选中的模型Key；分组Key不参与余额鉴权。

站点的完整Base URL包括路径，不能只凭origin合并模型入口；余额请求仍只能发到其同一origin的已配置路径。变更站点origin时，有绑定凭据则拒绝直接替换，须新建站点并重新录入凭据，防止旧Key被送到另一家平台。同origin路径修改也使旧查询结果失效。

RPC只返回白名单元数据，不返回secret及凭据摘要。身份备注只在用户自己的面板显示，不纳入测试日志/审计报告。禁止把secret放localStorage、URL、错误消息或余额结果中。

## 首版协议范围
| 协议 | 请求/结果 | 配置默认值与限制 |
|---|---|---|
| Sub2API | 单次Bearer GET `/v1/usage`；保留限额Key及严格钱包分支 | 用户显式确认USD或CNY，倍率1；订阅/未知模式继续拒绝，不能将remaining猜成钱包 |
| New API | 单次Bearer GET已确认token-usage路径；保留code=true、类型/值域严格校验、可选user_quota | 默认不自动启用；原始QUOTA倍率1，不猜美元人民币换算。不自动请求status探测倍率 |
| DeepSeek官方 | 单次Bearer GET `/user/balance`；按响应CNY/USD分开总可用/赠金/充值 | 仅明确官方origin `https://api.deepseek.com`；不把中转站DeepSeek模型Key发给官网。失败/字段异常不显示零 |
| 未配置/不适用 | 可以维护站点账号；查询给原因 | AFB、SAP、智谱普通余额等不猜接口；NVIDIA试用、本地/内网不伪装资金钱包 |

新增站点默认未配置查询，不因域名、模型名或OpenAI兼容自动启用。允许用户在站点设置中明确选择已支持的协议；保存配置本身不联网，也不表示该站已实测通过。一枝春保持当前已授权实测契约；跃数/幻城只作为已知候选，live确认另行授权。

麦块云登录Token、WorkBuddy/DeepSeek登录渠道、火山AK/SK签名不在首版认证支持内；可以建档标注待接入，不能把这些秘密误存成可被模型Bearer查询的Key。未来加独立凭据kind及协议，不复用本版模型Key类型。

## 旧账号迁移（代码提供能力，不操作当前真实数据）
1. schema1读取保留兼容，现有账号查询仍按旧全局配置执行；UI明确提示“旧格式，迁移后可使用多站点管理”。只查看/查询不自动改写文件，旧格式编辑先提示迁移。
2. 面板提供迁移预览/确认。预览不写入：每条旧账号保留原ID、name、baseURL、apiKey和groupKey；相同完整Base URL及相同查询配置可共享站点，账号与凭据绝不按邮箱或Key合并。
3. 迁移时只复制已有效的旧查询配置，不根据此次供应商审计猜单位或补账号身份；无法确认的配置保持未配置。迁移前后同一预览生成的ID映射应稳定，不以Key明文/哈希派生ID。
4. 用户点击明确确认后，宿主在原写锁内校验revision及同实例已批准预览绑定的文件快照/完整密文摘要、固定旧配置和ID映射；无预览、实例重建或同revision文件变化要求重新预览。校验通过才保留完整旧加密文件的独占备份，原子提交schema2并增加revision。备份失败、锁竞争、配置/文件冲突、DPAPI失败、写入超容量必须保留原文件、报告失败。
5. 备份不得覆盖已有文件；成功返回的public snapshot顶层 `migrationBackup` 为完整备份basename，仅此字段确认成功备份，不是 `backup` 或 `backupName`；提交后未知结果要求重新载入，不盲目重跑迁移；重复迁移schema2应返回已迁移而不新建重复账号/备份。
6. schema2不再从全局balanceQuery兜底取协议，站点为唯一owner；旧全局配置仅留在schema1兼容读取路径，适用范围可测试。旧1.0.2拒绝schema2而不覆盖，不能承诺无损直接降级。
7. 回退真实数据时需要用户停止所有相关实例、核对新版本迁移后是否又编辑过；保留当前schema2并恢复匹配的加密备份。不得自动回滚丢掉迁移后的新账号/Key，不输出一键覆盖真实vault的命令。

## 宿主和查询契约
站点/账号/凭据的创建、修改、删除都走同一个revision+锁+DPAPI事务；站点有关联账号时不级联删除，选中凭据删除/改kind会清空选择并明确禁止查询，删除账号须用户确认才连同其凭据删除。所有写请求采用明确动作/字段白名单，拒绝跨账号credentialId、伪造siteId和额外控制字段。

旧save/remove公开入口属于已分发契约，只用于schema1，schema2明确拒绝旧写载荷并提示升级UI；新增站点/账号/凭据RPC使用有名request。查询仍只接受account id和revision，浏览器不能提交任意origin、路径、Header、Key或协议。返回需增加站点/所选凭据的非敏感ID，使客户端校验归属；凭据值只在宿主请求生命周期内使用。

继续维持：公网HTTPS、同origin、禁重定向/代理/Cookie/模型调用、公共DNS校验与固定连接、10秒网络超时/64KiB JSON、12秒宿主期限、全局4并发/每账号1在途；没有自动重试。RPC超时不释放仍在进行的不可取消底层工作，不允许迟到读取开始新的网络请求。

配置错误在发网之前拒绝；schema2站点配置位于加密状态中，必须读取状态才能检查，不承诺“无任何vault I/O”。无用户动作时仍不解密账户文件/不联网。任何站点/账号/凭据修订、迁移、删除、切换Key、关闭面板都会使对应旧结果无效；宿主查询后再次验证revision，迟到结果不回显。查询失败时上次结果只能标“上次成功结果（非本次）”。

## 验收标准
1. 同站两账号、不同身份标签和不同Key可独立保存/修改/删除；同账号多Key明确选择一把，切换Key不显示上一把结果。
2. 两站采用不同协议和单位，查询只使用所属站配置及所属账号所选Key，无跨站/跨账号凭据外泄。
3. 新账号无Key/站点无协议时显示未配置；未知模式、鉴权失败、超时、字段异常不是零。合法零、负钱包余额、小数精度保留原约束。
4. schema1预览不写盘；确认后原ID/secret内容完整保留，备份独占、幂等、冲突拒绝；没有密钥明文日志。旧版遇schema2不能覆盖。
5. 原Sub2API/New API、DPAPI、文件竞争、查询并发、RPC有名参数、旧成功标记及ModuleLoader挂载回归通过；新增DeepSeek多币种和钱包/Key缺失语义覆盖真实宿主生成代码路径。
6. 浏览器或现有可用UI测试环境操作真实升级构建产物，验证站点/账号/Key选择、迁移确认、删除确认与错误可见；使用隔离测试账户文件，不触发真实供应商请求。若真实GUI受部署/登录权限限制，明示未验收，不以模拟钩子测试冒充真实GUI验收。
7. 构建产物与源码对应、离线包内容与manifest匹配，版本统一1.1.0，无新增依赖、不改DSH宿主、不自动安装/重启/迁移当前真实vault。
