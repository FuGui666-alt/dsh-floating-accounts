# 1.2.0供应商导入实现计划

依据[冻结规格](<../docs/provider-import-spec.md>)与[T1只读取证](<../artifacts/provider-import-2026-11-20/host-provider-storage-evidence.md>)。目标：用户在面板主动从DSH宿主配置导入供应商（含Key）到本插件vault：只读列出→勾选→两步确认→单事务DPAPI写入→可选引导协议检测。安装1.1.1原代码与真实vault保持不动；真实导入/安装仍以用户每次显式授权为准。

## 基线/必要性/边界
现有vault无任何“从宿主取Key”通道，用户迁移Key只能手抄明文；T1已证据化读取链、hasKey原语与DTO红线，新增“只读列出+确认写入”两接缝是必要最小改动。继续唯一AccountVault/transact owner，不新增schema字段、不第二vault、零新依赖、不新增网络行为。真实vault本轮只读（hash对照），测试只用synthetic fixture。
TDD Route: Mode=off, Decision=skipped, Strict authority=not applicable, Test posture=新增功能后回归。无Git仓库不建branch/commit。

## 实施步骤与写scope
1. Lead写 src/host-providers.js：readDshProviders（层序profile→home→settings段；profileDir=DSH_PROFILE_DIR→`profiles/DSH_PROFILE||desktop`回退；白名单YAML子集解析，超集结构整层降级不可读）与planImport纯函数（origin计算、单站合并/多站冲突/新建三分支、targetSiteId解析）；导出面不含resolve，模块禁import http/net/fetch。验证：新tests/provider-import.test.mjs纯fixtures覆盖DTO白名单、合并四分支、子集解析降级、字节不变、错误码表。
2. Lead在src/vault.js新增importFromDsh(input)唯一新写入口：请求形状校验（开锁前）→复用transact单事务（锁内重验载荷对应/冲突/容量/4MiB）→新建站点(balanceQuery=null)或在同origin现有站下新增账号→凭据kind=model-api-key、label=providerId、secret经现有DPAPI→revision+1；沿用原错误码家族，任一失败原文件未覆盖。不改旧方法与旧测试。
3. Lead改src/index.js：listDshProviders（result包装；AccountError透传；非预期→STORAGE_FAILED兜底）、importDshProviders（独立catch：AccountError透传；非预期→IMPORT_FAILED固定文案）；version→1.2.0。新tests/provider-import-host.test.mjs真实SDK carrier：Remote名单、args={}、写分类RESULT_UNKNOWN语义；更新rpc-contract写方法断言（加importDshProviders），不删旧断言。
4. delegate UI实现者only src/client.js/style.css/tests/provider-import-client.test.mjs：供应商列表区（安全DTO渲染、hasKey徽标、冲突清单与targetSiteId选择）、两步确认（预览变更清单→固定confirmText=`确认导入`按钮，无一键导入）、成功后“检测协议”引导复用现有账号按钮（不自动触发）；client.js writing分类加importDshProviders、错误映射表补DSH_SOURCE_UNAVAILABLE/IMPORT_CONFLICT/IMPORT_FAILED。只渲染冻结DTO，不新增字段。
